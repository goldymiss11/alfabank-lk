# Умный кредитный кабинет предпринимателя

Прототип цифрового кредитного конвейера для малого и микробизнеса, разработанный для хакатона **Альфа-Хак 2026** (кейс АО «Альфа-Банк»).

Сервис связывает клиентский путь предпринимателя (выбор продукта, расчёт лимитов, подача заявки, подписание договора) и внутреннюю обработку банком (обогащение данных, скоринг, кредитная политика, АРМ андеррайтера) в единый интерактивный интерфейс.

---

## Быстрый запуск

Для запуска требуется только **Docker** и **Docker Compose**:

```bash
docker compose up --build
```

После старта перейдите в браузере:
- **Интерфейс (Кабинет + АРМ банка):** [http://localhost:3000](http://localhost:3000)
- **API бэкенда:** [http://localhost:8000](http://localhost:8000)
- **Health Check:** [http://localhost:8000/health](http://localhost:8000/health)

Остановить проект:
```bash
docker compose down
```

## Стек технологий

- **Бэкенд:** Go 1.22, написан исключительно на **стандартной библиотеке** (`net/http`, `sync`, `encoding/json`, `math`, `crypto/rand`). Без сторонних фреймворков и внешних сетевых зависимостей. Потребление памяти в контейнере — менее 15 МБ.
- **Фронтенд:** React 19, TypeScript, Tailwind CSS, Zustand, Recharts, Lucide Icons.
- **Инфраструктура:** Docker Compose, мультистейдж сборка (Alpine Linux), Nginx с проксированием `/api` на Go-сервер.

## Возможности и логика конвейера

1. **Режим Split-Screen:** В реальном времени отображает интерфейс в двух колонках: слева — то, что видит предприниматель, справа — как заявку обрабатывает банковский конвейер.
2. **Двухступенчатая оценка:**
   - **Скоринг риска:** расчёт балла (500 базовых + дельты по ЕГРЮЛ, ФНС, БКИ, оборотам), вероятности дефолта (PD) и риск-грейда от A до E.
   - **Кредитное решение:** расчёт доступных лимитов по чистому доходу (15% от оборота) и DTI (до 50%), аннуитетный платёж.
3. **Адаптивные контр-офферы:** Если запрошенная сумма превышает лимит без залога, конвейер не отказывает, а предлагает матрицу из 3 вариантов: уменьшенная сумма, обеспечение под поручительство Корпорации МСП, либо другой продукт.
4. **План оздоровления (Rehabilitation Plan):** При отказе клиент получает понятную дорожную карту (сроки, действия, дата повторной подачи).
5. **Роли и делегирование:** Переключение между ролями «Собственник» (выбор, подписание ПЭП) и «Бухгалтер» (дозагрузка отчётности, ответы на уточнения банка).
6. **АРМ Андеррайтера:** Обработка нестандартных заявок (`MANUAL_REVIEW`), запрос пояснений и документов, принятие решений с указанием лимита и ставки.
7. **Господдержка и AI-советник:** Подбор программ субсидирования ставок по коду ОКВЭД и контекстный ассистент по кредитным продуктам.

## Структура проекта

```
.
├── backend/                  # Бэкенд на чистом Go
│   ├── internal/
│   │   ├── conveyor/         # Скоринг, кредитная политика, FSM, пресеты
│   │   │   ├── engine.go     # Двухступенчатый расчёт скоринга и решений
│   │   │   ├── engine_test.go# Юнит-тесты кредитной логики
│   │   │   ├── fsm.go        # Конечный автомат (15 состояний)
│   │   │   └── data.go       # Данные демонстрационных пресетов
│   │   ├── handlers/         # REST API маршруты
│   │   └── store/            # In-memory хранилище (sync.RWMutex)
│   ├── uploads/              # Директория загруженных документов
│   ├── Dockerfile            # Сборка контейнера бэкенда
│   └── main.go               # Точка входа HTTP-сервера
│
├── frontend/                 # Фронтенд на React 19 + TypeScript + Vite
│   ├── src/
│   │   ├── components/       # Компоненты кабинета, конвейера, АРМ андеррайтера
│   │   ├── store/            # Состояние интерфейса (Zustand)
│   │   └── types.ts          # Модели данных
│   ├── Dockerfile            # Сборка фронтенда и упаковка в Nginx
│   └── nginx.conf            # Конфигурация Nginx и проксирование /api
│
├── docs/                     # Документация по требованиям кейса
│   ├── c4_architecture.md    # C4-диаграммы (Context, Container)
│   ├── state_machine.md      # Граф состояний заявки и правила переходов
│   ├── erd.md                # Модель данных (ER-диаграмма)
│   ├── openapi.yaml          # Спецификация OpenAPI 3.0
│   ├── test_scenarios.md     # Пошаговые сценарии для тестирования
│   └── postman_collection.json # Коллекция запросов Postman
│
├── docker-compose.yml        # Конфигурация запуска всех сервисов
├── THIRD_PARTY_NOTICES       # Перечень внешних компонентов и мок-интеграций
├── .env.example              # Пример переменных окружения
└── README.md                 # Описание проекта
```

## Локальная разработка без Docker

### Бэкенд (Go)
```bash
cd backend
go test ./... -v    # запуск юнит-тестов
go run main.go      # запуск сервера на :8000
```

### Фронтенд (Node.js)
```bash
cd frontend
npm install
npm run dev         # запуск dev-сервера на :5173
```
Vite автоматически перенаправляет запросы `/api` на `http://localhost:8000`.
